## 1. 静音剪除不受转录词保护 —— 存在，最高优先级

上游对应 4 个 commit：`Protect silence cuts with transcript words` /
`Subtract protected words from silence cuts` /
`Preserve silence safety after word subtraction` / `Make silence removal fail safely`。

**现状**：`Sources/PalmierPro/Editor/ViewModel/EditorViewModel+DeadAir.swift`
的 `deadAirSourceRanges(for:settings:)` 只消费 VAD 掩码
（`mediaVisualCache.deadAirMask` / `quietNonSpeechMask`），全程没有引用转录文本。

**故障场景**：轻声说话、气声、低电平采访音轨被 VAD 判为 quiet →
`removeDeadAir` / `removeAllDeadAir` 直接 ripple delete 掉真实人声，
且这是一次 undo 组内的破坏性编辑，用户往往在导出时才发现。

**修复方式**：

1. 从 `TranscriptCache`（`Sources/PalmierPro/Transcription/TranscriptCache.swift`，
   `actor`，有 `cachedOnDisk(for:)` 这种 nonisolated 入口）取该 mediaRef 的
   `TranscriptionResult.words`，得到 `[TranscriptionWord]`（`start`/`end` 为秒，可选）。
2. 把词区间（各加上 `settings.speechPaddingSeconds`）换算到
   `VoiceActivity.chunkDuration` 的 cell 下标，从 **quiet mask** 里扣除——
   即在调用 `SilenceRemovalPlanner.removableMask(from:settings:)` **之前**扣，
   而不是从最终 ranges 里扣。上游第三个 commit
   （`Preserve silence safety after word subtraction`）修的正是这个顺序：
   先扣词再跑 planner，最小停顿长度与 padding 才会在扣除后重新成立；
   反过来做会切出一堆碎片化的短段。
3. 失败安全：转录缺失 / 加载失败 / 词缺 `start` 或 `end` 时，
   必须**收缩**可剪范围（宁可少剪），不能当作"没有词需要保护"照剪。
   对应上游 `Make silence removal fail safely`。
4. 单一真相：扣除逻辑放进 `SilenceRemovalPlanner`，让时间线阴影预览
   （`deadAirRanges`）和实际剪除（`removeDeadAir*`）走同一条路径，
   否则预览显示的可剪区与真正剪掉的区域会不一致。
5. 缓存键：`DeadAirMaskCache.Key` 目前只含 group/member/settings，
   加入转录版本标识（如 transcript 的 fileTag），否则转录完成后掩码不失效。

**回归测试**：构造一段 VAD 判 quiet 但转录有词的音频 fixture，
断言该区间不出现在 `deadAirSourceRanges` 结果里；
再断言扣除后仍满足 `minimumPauseSeconds` 下限。

## 2. `set_keyframes` MCP schema 缺 `maskPath` —— 存在，改动最小

上游对应：`Correct keyframe MCP schema types`。

**现状**：`Sources/PalmierPro/Agent/Tools/ToolDefinitions.swift:625` 的 enum 是

```
["volumeDb", "opacity", "rotation", "position", "scale", "crop", "blur"]
```

但同一工具的 description 明确写了 `maskPath` 的行格式，`track_subject` 的
description 也指示 agent "用 set_keyframes maskPath 手动微调"，
而执行器 `ToolExecutor+Clips.swift:1019` 的 `keyframePropertyNames` **包含**
`maskPath`，`:1081` 有完整的 `case "maskPath"` 分支。schema 与实现不一致。

**故障场景**：会做 inputSchema 校验的 MCP 客户端直接拒掉调用；
不校验的客户端则依赖模型忽略 enum 才能碰巧成功。蒙版动画路径实质不可用。

**修复方式**：

1. enum 补上 `"maskPath"`。
2. 让 enum 由 `ToolExecutor.keyframePropertyNames` 派生（或反向），
   消除两处各写一份的重复。
3. `keyframes.items` 目前是裸 `["type": "array"]`，行内元素类型无约束。
   `maskPath` 行是 `[frame, [[x,y],…], interp?]`（数字 + 嵌套数组 + 字符串混合），
   其余属性是纯数字行。至少给出 `minItems` 和 description 级别的区分。

## 3. 媒体元数据 / 缩略图在主 actor 上构造 AVFoundation 对象 —— 存在

上游对应：`Move media metadata and thumbnail setup off main`。

**现状**：`Sources/PalmierPro/Models/MediaAsset.swift` 是 `@MainActor` 类型。
图片分支用了 `Task.detached`（:221、:316），但视频/音频分支没有：

- `:262` `let avAsset = AVURLAsset(url: url)`
- `:292` `let gen = AVAssetImageGenerator(asset: avAsset)`

两个构造都在主 actor 上执行。`AVURLAsset` 初始化会碰文件系统，
`AVAssetImageGenerator` 初始化会做解码器准备。

**故障场景**：从慢速外置盘、网络卷或大批量导入时主线程卡顿；
`metadataLoadGate`（并发 4）只限制了并发数，没有换执行器。

**修复方式**：把 `loadMetadata` 中视频/音频分支的资产构造与属性加载整体移进
`@concurrent` 函数或 `Task.detached(priority: .utility)`，
只把最终的不可变值（duration / 尺寸 / CGImage）带回主 actor；
回到主 actor 后按 AGENTS.md 的要求重新校验 `url == snapshotURL` 与 `Task.isCancelled`
（图片分支 :226 已经这么做了，照抄即可）。

## 4. MCP 启动失败不可见、无重试 —— 存在

上游对应：`Surface MCP startup failures` / `Decouple in-app MCP listener`。

**现状**：`Sources/PalmierPro/Agent/MCP/MCPService.swift:59`

```swift
} catch {
    Log.mcp.error("http server failed to start: \(error.localizedDescription)")
    self?.isRunning = false
}
```

仅写日志。端口被占用（`MCPService.swift:9` 固定 19789）时，
用户侧唯一表现是"外部 agent 连不上"，没有任何提示，也没有重试。

**修复方式**：把失败转成可观测状态——`isRunning` 之外增加带错误原因的
状态枚举，在 Agent/设置面板呈现，并提供重试入口；
监听器启动与服务注册解耦，使监听失败不至于让整个 MCP 服务不可恢复。

## 5. MCP session 不绑定所属项目 —— 存在

上游对应：`Bind in-app MCP sessions to owning projects` / `Isolate Palmier runtime storage by project`。

**现状**：`MCPService` 由 `AppState.shared` 单例持有
（`Sources/PalmierPro/App/AppState.swift:52`），固定端口，
`projectProvider` 闭包返回"当前项目"。

**故障场景**：多窗口 / 多项目时，外部 MCP 客户端的调用会打到
恰好处于活跃状态的那个项目上——包括破坏性编辑工具。
切换项目会让进行中的 agent 会话静默改写另一个项目。

**修复方式**：会话建立时把项目身份钉进 `ToolExecutor`
（`makeSessionToolExecutor()` 已是 per-session，把项目快照而非
provider 闭包注入即可），项目关闭后该会话的后续调用返回明确错误而不是落到新项目上。
